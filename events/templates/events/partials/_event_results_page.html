Used both for the initial full-page render and for htmx's infinite-scroll fragment requests (see https://htmx.org/examples/infinite-scroll/). The hx-get trigger goes on the *last date-group div* of the page, not on the last event-row: rows live inside a date-group, and htmx's hx-swap="afterend" inserts the next page as a sibling of whatever element the trigger is on, so putting it on a row would nest the next page's date-group(s) inside the current one instead of after it. Note: each page's {% regroup %} only groups within that page's slice, so if a date's events straddle a page boundary, that date's heading can appear twice in a row — a minor, accepted trade-off of paginating grouped data rather than something worth the added complexity to avoid.
