### API: OAuth 2.0 client credentials for a dojo's apps

`DATA_MODEL.md` §13 has the plan; built so far: dojo clients and attendance. An app that works for a dojo (e.g. scanning children in at the door) is an `api.DojoApiClient`, made by the dojo's **champion** on the dojo's API page (`MANAGE_API`, champion only) through `api/services.py` (`create_client`, `renew_secret`, `delete_client`; `ApiClientError`). Each client is a django-oauth-toolkit `Application` (confidential, **client credentials grant only**; the secret is shown once and stored hashed), a set of `scopes` (`attendance:read`, `attendance:write`; `api.scopes.ClientScopes` gives a client only its own) and its own **technical account** (`User.account_type = "service"`, unusable password): what `TeamAttendance.marked_by` and the audit log's actor point at. Service accounts are never people: retention and account deletion skip them, segments only take adults. Deleting a client removes it, its `Application` and its tokens at once, and switches its account off; the account stays for the history. There is no separate "revoked" state.
- **Tokens:** `POST /api/oauth/token/` (`grant_type=client_credentials`, HTTP Basic with client ID and secret), one hour (`OAUTH2_PROVIDER` in settings); revoke at `/api/oauth/revoke/`.
- **Endpoints** (`api/v1.py`, reference at `/api/v1/docs`): `api.auth.OAuth2(scope)` checks the token (401) and the scope (403) and makes `request.auth` the client; an endpoint takes it as `**read.operation(summary=...)` with `response={200: ..., **ERRORS}`, so the OpenAPI spec describes the login as OAuth 2.0 (an `OAuth2` scheme with the client credentials flow, token URL and scopes, and each endpoint's own scope: `api.v1.ScopedNinjaAPI`, since django-ninja has no scopes of its own; `test_the_spec_describes_oauth2_client_credentials_and_scopes`) and OAuth-aware tools, the reference page's Authorize button included, fetch the token themselves; every endpoint only reaches the client's own dojo (another dojo's row is a 404). Writes run under `auditlog.context.set_actor(client.account)` and go through the same code as the site: attendance is `events/attendance.py` (`mark_child`, `mark_team_member`, `mark_all_present`, shared with the dojo views). Requests per client are throttled (`API_RATE_LIMIT`, on the cache).
- **Never in the API:** a field classified `special`, `criminal` or `security`, or anything `export=False` — `api.tests.AttendanceApiTests.test_the_schema_never_holds_sensitive_fields` checks the OpenAPI schema against the privacy registry. A new endpoint picks a scope, goes through a shared service, and passes that test.
- django-oauth-toolkit 3.4.1 officially lists Django up to 6.0; our tests run it on 6.1. Its admin blocks adding tokens and deleting them raw (tokens are ended with its Revoke action); those are listed with their reason in `AdminStaysFullyUsableTests.EXCEPTIONS`.
