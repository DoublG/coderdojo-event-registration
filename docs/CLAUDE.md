### Documentation outputs: the help centre on GitHub Pages, user journeys, pitch deck, technical PDF

- **The help centre is published by GitHub Actions**, not by `deploy.sh`: `.github/workflows/docs.yml` builds `docs/` (`make html-all`, en/fr/nl) and deploys it to GitHub Pages, `https://doublg.github.io/coderdojo-event-registration/` (`fr/`, `nl/`), on every push to main that changes `docs/` or the workflow (or by hand: Actions tab, *Run workflow*). The repo's Pages source must stay on **"GitHub Actions"**: "Deploy from a branch" runs GitHub's Jekyll build over the whole repo instead, which fails (Liquid chokes on the Django tags quoted in this file). The build treats Sphinx warnings as errors, so a docs change that warns fails there: build it locally first the same way (`make html-all BUILDDIR=/tmp/pagesbuild SPHINXOPTS="-W --keep-going"` inside `docs/`, a scratch `BUILDDIR` so the served `docs/build/` isn't touched). A fresh checkout only has what git tracks: `docs/source/_static` and `_templates` are kept by a `.gitkeep`, since an empty folder that Sphinx expects is a warning. The language switcher's links come from `DOCS_BASE_URL` in `docs/source/conf.py` (default `/docs/`, the devcontainer's path; the workflow sets the Pages path). Publishing needs no one to push anything but the change itself; a failed run shows in the Actions tab, and a re-run always builds the commit it was made for.
- **The user-journey PDFs** (`user-journeys/`, details in its README) are made from the host, through nginx, by Playwright scripts in `user-journeys/scripts/` with a local venv (`playwright pillow pyotp`) and Google Chrome: one `j_<persona>.py` per persona (`parent`, `ninja`, `volunteer`, `champion`, `reviewer`, `org`) drives a headless Chrome with a seeded login from `seed_credentials.csv` (two-step codes computed from its `totp_secret`) and saves screenshots plus the English captions to `user-journeys/.shots/<lang>/` (gitignored); `JLANG=nl|fr` switches the site's language cookie; `build.py <lang>` lays them out into `user-journeys/<lang>/*.pdf`, with the Dutch and French captions in `nl.py` and `fr.py` (a new step needs its text in both). Then `manifest.py` (inside the workspace container: it resolves the captured URLs with Django) writes `user-journeys/manifest.json`, the baseline for `check_journeys.py` (the workflow rule above). **They change dev data**: the parent and ninja journeys book real places, the volunteer journey marks attendance, and the booking mail goes through the Celery workers to Mailpit (restart the workers first if they're stuck: the parent's mail step waits for it). The seeded ids they use (dojo 51, events 71/72/76, ninja 9, pathway 2, users 352, application 348) change when the database is reseeded. **Only screenshot whole pages:** an htmx endpoint opened on its own URL returns a fragment without the page shell or stylesheet (a child's `badges/` and `avatar/` are two), and a POST-only action URL (`manage/lifecycle/`) just redirects, so both make a useless screenshot. Open the page that loads the part and click to it (`page.click(...)`, then `shot`); `Journey.shot` refuses a page without the site's stylesheet from `/static/` (Mailpit's pages excepted).
- **The pitch decks** are Slides artifacts on claude.ai (links in `user-journeys/README.md`); `user-journeys/pitch-deck/<lang>/` is a copy of their slide files and `build_pitch.py en|nl` renders it to `user-journeys/en/pitch-deck.pdf` and `nl/pitchdeck.pdf`. Their facts and figures (commits, tests, lines, models, routes) are a snapshot of 5 October 2026: refresh them when asked, not on every change.
- **The technical foundation PDF** (`user-journeys/technical-foundation-and-data-model.pdf`, `build_technical.py`) takes its diagrams from `DATA_MODEL.md` as they are and its prose from the script: after a change to the model or these conventions, rebuild it when asked, and check the prose still holds. The build fails when a diagram doesn't render (Mermaid 11.4.1), which also catches a broken diagram in `DATA_MODEL.md` (`BOX` is a reserved word in a sequence diagram; a `;` ends a statement).
